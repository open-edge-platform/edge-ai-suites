# Export-only dependency pins for the OpenVINO model-conversion subprocess.
#
# Do NOT install these into the application environment -- they are deliberately
# older than requirements.txt. They are installed into a side directory that is
# prepended to PYTHONPATH for convert_worker.py only, by
# components/vlm/vlm_openvino_serving/utils/utils.py.
#
# Why: optimum-intel 2.1.0 advertises transformers>=4.51,<5.6, but its
# per-architecture support table caps Qwen3_5, Qwen3_5Moe, Qwen3_5Text and
# Qwen3_5MoeText at transformers 5.2.0. Qwen3.5-9B and Qwen3.6-35B-A3B both
# report model_type qwen3_5_moe, so they are governed by that cap, not by <5.6.
# Above 5.2.0 the export patcher fails with "cannot import name
# 'Qwen3_5DynamicCache' from transformers.models.qwen3_5.modeling_qwen3_5"
# (optimum-intel issue #1786). Inference is unaffected: it runs through
# VLMPipeline and never imports the patchers.
#
# Provisioned automatically on the first local export of an affected model.
# To pre-install it (offline hosts, or to keep the first conversion quiet):
#
#   python -m pip install --no-deps \
#       --target smart-classroom/models/.export-deps/transformers-5.2.0 \
#       -r smart-classroom/requirements-export.txt
#
# --no-deps is intentional: transformers 5.2.0 needs huggingface-hub>=1.3.0,
# tokenizers>=0.22.0,<=0.23.0, safetensors>=0.4.3 and typer-slim, all satisfied
# by the versions already pinned in requirements.txt, so only this one pure
# Python wheel is duplicated (~100 MB on disk).
#
# Revisit when an optimum-intel release raises the qwen3_5* row above 5.2.0;
# 2.1.0 is the newest release as of this pin.
transformers==5.2.0
